# Premiere-AE Video Workflow Guide

2026-09-30 · 김사부

## 이 문서의 사용법

새 채팅에서 Claude와 프리미어·에펙 작업을 시작할 때 이 문서 링크를 먼저 주고 "이 가이드대로 작업해줘"라고 요청한다. 제작 흐름, 역할 분담, 컷 길이 기준, 파일 규칙을 매번 다시 설명하지 않아도 된다.

- 작업을 시작하기 전에 Claude는 프리미어 연결(verify_premiere_connection)과 에펙 연결(check-bridge)을 먼저 확인한다.
- 기준이 바뀌면 이 문서를 직접 고치거나 Claude에게 수정을 요청해 최신 상태로 유지한다.

## 전체 제작 흐름

영상 편집은 세 단계로 진행하고, 오디오 소스 제작은 이와 별도로 병행한다.

1. **OK컷 작업**: 촬영본에서 쓸 테이크를 고른다.
2. **가편집**: 시퀀스 순서를 맞추고, 나레이션에 맞게 컷을 배치한다.
3. **본편집(마스터 편집)**: 자막, 색보정, 합성(에펙 작업), 오디오 믹싱을 한다.

**별도 오디오 작업 영역**: 나레이션 녹음, 배경음악 선곡 또는 제작, 효과음 선곡 또는 제작. 별도 프로그램이나 무료 라이브러리를 사용하고, 완성된 파일을 프리미어로 가져와 가편집과 본편집에 쓴다.

## 단계별 역할 분담

연출적 판단은 사용자가 하고, Claude는 정리·배치·측정·검수를 맡는다.

| 단계 | 사용자 | Claude |
|---|---|---|
| OK컷 | 테이크 판정 (연기, 초점, 흔들림, 타이밍) | 촬영본 빈 정리, 포맷 혼재 확인, 테이크별 대표 프레임 캡처, OK컷에 컬러 라벨·마커 표시, 서브클립 생성 |
| 가편집 | 컷 순서(콘티) 결정, 문장별 사용할 컷 지정 | OK컷 이어 붙인 시퀀스 조립, 나레이션 무음 분석으로 문장 경계 마커, 원고 문장 번호와 타임코드 연결, 문장 길이에 맞춘 컷 배치, 비트 분석 |
| 본편집: 자막·합성 | 동적 링크로 에펙 보내기, 디자인 결정 | 에펙 컴포지션 구조 읽기, 자막 레이어·애니메이션 작업 보조, 프레임 캡처로 결과 확인 |
| 본편집: 색보정 | 세밀한 그레이딩, 최종 룩 판단 | 컷별 파형·RGB 퍼레이드 수치 측정, 튀는 컷 목록, Lumetri 기본값·LUT 적용 |
| 본편집: 오디오 믹싱 | 음색·밸런스를 귀로 최종 판단 | 트랙별 레벨 정리, 나레이션 구간 음악 더킹 키프레임, 효과음을 마커 위치에 배치 |
| 납품 전 검수 | 최종 승인 | 플래시 프레임, 빈 구간, 오프라인 미디어, 라우드니스(LUFS), 자막 안전 영역 점검 |

## 에펙 연계 규칙

자막과 합성은 에펙에서 만들고, 프리미어에서 동적 링크로 보낸다.

1. **보내기**: 프리미어에서 클립 우클릭 → "After Effects 컴포지션으로 바꾸기(Replace With After Effects Composition)". 스크립트로 제어할 수 없으므로 사용자가 직접 실행한다.
2. **이름 짓기**: 컴포지션 이름은 영문으로 역할과 컷 번호를 붙인다. 예: `Title_Cut05`, `Comp_Cut12`. 기본 이름("시퀀스명 Linked Comp 01")은 여러 개가 생기면 구분이 어렵다.
3. **에펙 작업**: Claude가 컴포지션을 읽고 작업을 돕고, 프레임을 캡처해 자막 잘림·안전 영역·합성 경계를 확인한다.
4. **프리미어 확인**: 동적 링크는 자동 반영된다. 해당 구간을 프리미어에서 캡처해 원본과 이어지는지 확인한다. 링크 클립은 캡처가 느릴 수 있다.
5. **고정**: 작업이 끝난 컷은 "렌더링 후 바꾸기"로 고정해 프리미어 재생 부담을 줄인다.

에펙 연결 조건: After Effects에서 **창 → mcp-bridge-auto.jsx** 패널을 열어 두고, 환경 설정의 "스크립트가 파일을 쓰고 네트워크에 액세스하도록 허용"을 켠다.

## 장르별 컷 길이 기준

컷 배치와 리듬 점검은 아래 평균 컷 길이를 기준으로 한다.

| 장르 | 1컷 평균 길이 |
|---|---|
| 광고 | 약 2초 |
| 정보 프로그램 | 3~5초 |
| 다큐멘터리 | 3~5초 |
| 뉴스 | 3~5초 |

- **가편집**: 나레이션 한 문장이 길면 이 기준으로 컷 수를 나눈다. 예: 다큐에서 12초 문장 → 컷 3~4개.
- **리듬 점검**: 기준보다 너무 긴 컷(늘어짐)과 너무 짧은 컷(튐)을 목록으로 뽑는다.
- **버전 편집**: 같은 소스로 다큐판과 광고·쇼츠판을 만들 때 기준을 바꿔 줄일 구간을 찾는다.

## 오디오 작업 원칙

오디오 소스는 외부 프로그램이나 무료 라이브러리로 준비하고, 프리미어에서는 받아서 맞춘다. Claude는 소리를 듣지 못하므로 수치 측정과 배치를 맡고, 음색 판단은 사용자가 한다.

- **나레이션**: 녹음 파일을 가져오면 무음 분석으로 문장 경계에 마커를 찍는다. 원고를 주면 문장 번호와 구간(예: 3번 문장 = 12.4~16.8초)을 연결하고, 문장 사이 공백이 길면 줄이는 계획을 세운다.
- **배경음악**: 비트를 분석해 컷 전환 후보를 잡고, 나레이션 구간에 맞춰 음악을 낮추는 더킹 키프레임을 만든다.
- **효과음**: 들어갈 지점(컷 전환, 자막 등장, 클릭 동작 등)에 마커를 찍어 두면 그 위치에 배치한다.
- **최종 믹스**: 트랙별 레벨과 전체 라우드니스를 측정해 납품 기준(예: 유튜브 -14 LUFS, 방송 -24 LUFS)에 맞는지 확인한다.
- **무료 라이브러리 라이선스**: 출처 표기(CC-BY) 의무, 상업적 사용 제한, 유튜브 저작권 신고 여부를 곡마다 확인하고, 출처와 라이선스를 기록해 둔다. 훈련생 실습에서도 같은 습관을 잡는다.

## 스틸 캡처 규칙과 작업 환경

"MM:SS 스틸 만들어줘"라고 하면 Claude는 캡처 → PNG 저장 → 프로젝트 패널 가져오기를 한 번에 처리한다.

1. 해당 시점을 캡처해 Claude가 화면을 확인하고 설명한다.
2. 같은 프레임을 `D:\prmcp\`에 PNG로 저장한다. 파일명은 시점을 따라 `frame_0400.png` 형식(04초 00프레임)으로 붙인다.
3. 저장한 파일을 프리미어 프로젝트 패널로 가져온다. 스틸이 많아지면 `Stills` 빈에 모은다.

**작업 환경 메모**

- 프로젝트 파일: `D:\prmcp\project files\` / 촬영 소스: `D:\prmcp\film sources\`
- 프레임 캡처는 Adobe Media Encoder(AME)가 설치돼 있어야 동작한다.
- 시퀀스, 소스 파일, 컴포지션, 생성 파일 이름은 영문으로 짓는다.
- 타임코드 표기 "04초21프레임"은 29.97fps 기준 약 4.705초로 환산한다(시퀀스 프레임레이트에 따라 달라짐).

## 도구의 한계와 주의사항

도구로는 되돌리기(Undo)가 지원되지 않으므로, 큰 변경 전에는 저장(Ctrl+S)이나 백업을 하고 내용을 확인받은 뒤 실행한다.

- **사용자가 직접 해야 하는 작업**: 동적 링크로 에펙 보내기, 클립 속도 변경, 역재생, 캡션(자막 트랙) 생성, 소스(프로젝트 아이템)에 붙은 마커 삭제(소스 모니터 → 마커 → 모든 마커 지우기).
- **Claude가 볼 수 있는 것**: 정지 프레임 캡처, 타임라인 구조, 클립 효과·키프레임, 시퀀스 설정, 라우드니스·무음·비트·장면 전환 분석, 스코프 수치.
- **Claude가 볼 수 없는 것**: 재생 중인 움직임(여러 프레임으로 추측만 가능), 소리 자체(수치만 측정 가능).
- **요청 요령**: "3초~10초 구간 자막 위치 확인해줘"처럼 구간과 확인할 항목을 짚어 주면 가장 정확하다.
- **장면 편집 감지**: 컷 나누기(ApplyCuts)를 하면 전환 효과 구간에서 0.1~0.4초짜리 짧은 컷이 생길 수 있으니 결과를 확인한다.
